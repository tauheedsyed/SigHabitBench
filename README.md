# SigHabitBench

Do large language models know how specific proteins regulate each other, or do they
fall back on what each protein *usually* does?

Most proteins act in one dominant direction — some mostly activate their partners,
some mostly inhibit. SigHabitBench asks each model about the **same protein twice**:
once for an interaction that follows the protein's habit and once for an interaction
that contradicts it, matched on the number of supporting publications. Answers are
balanced 50/50 between "stimulates" and "inhibits", so random guessing and pure
habit-following both score 50%.

- 108 human proteins, 216 questions, built from an OmniPath snapshot (22 Aug 2026)
- 16 models from 8 developers; 10,988 stored responses
- Controls: reversed answer order, 120 fabricated protein pairs, a per-protein habit
  probe, web retrieval (2 models), a blinded label audit

## Layout

| Path | Contents |
|---|---|
| `data/processed/` | Benchmark (`sighabit_v2.jsonl`), benchmark + fabricated pairs (`sighabit_v2_full.jsonl`), habit probes (`sighabit_v2_usually.jsonl`), prompts, eligible proteins, protein classes, observed providers |
| `data/raw/snapshot_manifest.json` | Download date, package version and SHA-256 of the OmniPath snapshot (the snapshot itself is not redistributed, see below) |
| `results/` | Every stored model response, one file per model and arm (`main`, `swap`, `usually`, `web`) |
| `notebooks/` | Numbered in run order (see below) |
| `figures/final_set/` | Figures 2–4 (PNG, PDF, SVG). Figure 1 is a hand-drawn schematic and is not generated by code |
| `supplementary/` | Supplementary Tables S1–S6, Supplementary Figure S1 (biomedical adaptation) and `supplementary_numbers.json` |
| `docs/` | Label-audit worksheet (with the annotator's verdicts and quotations) and answer key |

## Reproducing the results

```bash
pip install -r requirements.txt
cd notebooks
jupyter nbconvert --to notebook --execute --inplace 04_analysis.ipynb 05_label_audit.ipynb 06_figures.ipynb
```

| Notebook | What it does | Needs |
|---|---|---|
| `01_feasibility` | Downloads OmniPath, filters to signed interactions, selects eligible proteins | Internet |
| `02_build_benchmark` | Builds the matched pairs, fabricated pairs and habit probes | OmniPath snapshot in `data/raw/` |
| `03_run_models` | Queries the models and stores every attempt | API keys in `.env` (see `.env.example`); costs money |
| `04_analysis` | Every number in the paper; writes Tables S1, S3–S5 | Stored responses only |
| `05_label_audit` | Scores the blinded label audit; writes Table S2 | Stored responses only |
| `06_figures` | Figures 2–4 and Supplementary Figure S1 | Stored responses only |
| `07_robustness` | Re-analysis on protein subsets; writes Table S6 | OmniPath snapshot in `data/raw/` |

Notebooks 04–06 run offline on the stored responses and never contact a model.
Re-running 03 would query the models again; at temperature 0.3 the answers would not be
identical, so the stored responses in `results/` are the record of this study.

### OmniPath snapshot

The raw OmniPath tables are not included because several of the resources OmniPath
integrates carry their own licences. `01_feasibility` re-downloads them with
`omnipath==1.0.12`; compare the files against the checksums in
`data/raw/snapshot_manifest.json`. A newer OmniPath release may differ. The snapshot is
available from the authors on request. Notebook 02 rebuilds the published benchmark
byte-for-byte from the original snapshot.

## Use of AI tools

Parts of the analysis code and manuscript drafts were written with the help of large
language models and checked by the authors. Claude (Anthropic) was used to audit the
analysis, re-derive every reported number from the stored responses, and write
`07_robustness` and the cleaned versions of notebooks 04–06. The models evaluated in the
study were queried only through `03_run_models`.
